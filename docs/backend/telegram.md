# Сообщения бота и утренняя доставка

Личный чат даёт вход в Mini App. `TelegramWebhookRequest` проверяет секрет webhook и передаёт типизированное событие в `HandleTelegramUpdateAction`.

## Вручение по /start

`ClaimCalendarsAction` регистрирует личность Telegram и привязывает подходящие календари по ID или подтверждённому нику. Транзакция сохраняет адресата, список новых вручений и выбранный ответ. После окончательного коммита бот отправляет сообщение. Кнопка `web_app` ведёт на публичный HTTPS-адрес из `APP_URL`.

| Состояние при обработке команды | Сообщение | Куда ведёт кнопка |
|---|---|---|
| У человека ещё нет календарей | Текст с приглашением создать календарь | Новый черновик |
| Появился один новый календарь | Обычное фото с обложкой и подписью | Вручённый календарь |
| Появилось несколько календарей | Одна открытка на все новые вручения | Главная Mini App |
| Календари уже есть, новых вручений нет | Короткий текст | Главная Mini App |

Повтор одного `update_id` использует сохранённое решение о вручении. При недоступном файле обложки до сетевого вызова резерв освобождается. При ответе Telegram 429 webhook запоминает срок и возвращает 503 с `Retry-After`. При потере сетевого ответа резерв сохраняется от дублей. Одновременный обработчик того же обновления получает 503 с трёхсекундной задержкой. [Проверки повторов](../../backend/tests/Feature/TelegramStartReplayTest.php)

Поле `telegram_start_updates.outcome` хранит результат ответа на команду. Значение `sent` означает подтверждённую отправку, `retry` — ожидание после 429, `blocked` — блокировку, `failed` — явный отказ, `unknown` — отсутствие подтверждения. Код отказа хранится в `telegram_error_code`. Если Telegram явно отклонил открытку, новый /start позволяет вручить её снова. После обрыва связи открытка могла дойти. Повтор обновления сохраняет резерв от дублей.

## Уведомление за день

С 10:00 МСК команда `calendar:morning` выбирает вручённые календари с подарком на сегодняшнюю дату. При позднем /start отбор и воркер ждут подтверждения открытки для вручаемого календаря за этот день. После подтверждения бот сразу запускает отбор для получателя. При публикации себе отбор начинается после коммита публикации. PostgreSQL резервирует одну доставку на получателя и дату. Задание `SendMorningGift` поступает в очередь после коммита. В следующий день действует его собственное расписание.

Воркер определяет состояние дня и готовит короткое текстовое сообщение. Кнопка содержит ID календаря и полную дату, например `/app/received/42/2026-12-07`. Прочитанный подарок можно посмотреть ещё раз. Старое уведомление сохраняет свой адрес.

Перед вызовом Nutgram один воркер атомарно переводит доставку в `sending`. Подтверждённое сообщение и статус `sent` сохраняются вместе. При 429 воркеры соблюдают общий срок паузы и `retry_after`. Блокировка бота даёт `blocked`, повторный /start снимает отметку блокировки. Потеря ответа даёт `unknown` и требует сверки. Прошедшие дни не досылаются. Планировщик сверяет зависшие задания с очередью по идентификатору доставки.

## Журнал и локальная проверка

В `widget_messages` для новых сообщений сохраняются подпись, текст кнопки, путь Mini App и при наличии обложка и конкретная дата. Кнопка открывает адрес из `app_path` в Mini App.

В мастерской /dev выберите участника и московское время, затем запустите /start или утреннюю рассылку. Чат показывает тот же текст, обложку и маршрут кнопки, которые сформированы для Telegram. Локальный транспорт позволяет открыть экран этого участника. [Сценарии Telegram и мастерской](TESTING.md)
