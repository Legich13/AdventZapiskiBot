# Доменные модели

| Модель | Таблица | Связи и смысл |
|---|---|---|
| TelegramUser | telegram_users | Первичный ключ равен Telegram ID. Ник отражает последнее подтверждённое имя. Один человек может быть автором и получателем разных календарей. |
| Calendar | calendars | Автор закреплён с первого сохранения. Год и месяц задают период; до получения известен адресат, после вручения — ID получателя. Публикация и вручение отмечаются раздельно. |
| GiftDay | gift_days | Принадлежит календарю; дата определяет доступность в Москве. Автор хранит текст, первое успешное открытие заполняет opened_at. |
| WidgetMessage | widget_messages | Хранит получателя, подпись и кнопку сообщения. Для открытки задан путь фото. Уведомление ссылается на календарь и дату. У старых локальных виджетов сохранён HTML. |
| MorningDelivery | morning_deliveries | Одна запись на получателя и московскую дату. Содержит состояние попытки и связь с подтверждённым сообщением. Это источник состояния отправки. |
| User | users | Учетная запись сотрудника Filament. Роли и права хранятся в таблицах Spatie. Telegram ID получателя и ID сотрудника принадлежат разным пространствам. |

Для `/start` ведётся технический журнал. В `telegram_start_updates` для каждого `update_id` хранится Telegram ID и список новых вручений и выбор действия для кнопки. В `telegram_start_messages` пара `update_id` и позиции защищает ответ на команду от повторной отправки. Обе записи обходятся без текста подарков. [Обработка команды](telegram.md)

Ограничения на повторную публикацию, повторное открытие и неоднозначную отправку описаны в [основаниях модели](model-business-evidence.md). Поля, точные типы и внешние ключи задают Laravel/PostgreSQL migrations в `backend/database/migrations`.
