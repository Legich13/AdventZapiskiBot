# Проверки backend

| Набор | Наблюдаемый результат |
|---|---|
| Calendar | Публикация, смена ника, конфликт месяца, секретность будущих дней, гонка открытия, сессия Mini App, экраны месяца и дня, повторное чтение. |
| Telegram | Подлинность и границы webhook, поля обычного сообщения и фото, адрес кнопки, совместимость старых виджетов, доставка с 10:00, повторный update, отложенный и неизвестный ответ. |
| StudioTest | Производственные/локальные маршруты, видимость админки и переход между тестовыми профилями. Выбранная пользователем дата меняет часы подарков в пределах запроса. Сессия и ограничители частоты используют реальное время. |
| AdventArchitectureTest и TestNamingLanguageContractTest | Направление запросов, типы DTO, документация моделей и русские названия Pest. |
| DocumentationAccessTest | Защищённый доступ к /admin/docs, Scalar и JSON, проверка бизнес-операций в экспортируемой схеме. |
| ValidateFastPlanCommandTest | Корректные и повреждённые пакеты FAST_STRICT/2. |

Точечную проверку запускает `make test-suite suite=Calendar`. Меняйте значение suite для соответствующего проверяемого поведения. В RED нужна ошибка отсутствующего поведения, в GREEN — та же команда с кодом 0. Тесты конкуренции используют отдельные соединения с PostgreSQL. Нативный HTML дополнительно проверяется в официальном Telegram Widget Sandbox. Перед выпуском отдельно проверяются вручение и открытие уведомления в личном чате Telegram с тестовым получателем. Мастерская позволяет проделать тот же путь в браузере.
