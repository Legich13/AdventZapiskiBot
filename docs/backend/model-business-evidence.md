# Основания модели

| Модель | Бизнес-правило | Источник проверки |
|---|---|---|
| TelegramUser | После вручения смена username сохраняет владельца. | CalendarFlowTest, привязка при /start. |
| Calendar | Для получателя и месяца подтверждается одна публикация; вторая заявка сохраняет авторский текст. | CalendarFlowTest, конкурентная публикация на PostgreSQL. |
| GiftDay | Получатель читает только наступивший день. Повторное нажатие возвращает записку при одном открытии. | CalendarRecipientTest, CalendarFlowTest и TelegramWidgetTest. Открытие из Mini App и из ранее доставленного виджета. |
| WidgetMessage | Сервер проверяет сообщение, получателя и дату; старая карточка сохраняет свою дату. | TelegramWelcomeWidgetTest, TelegramWidgetTest и CalendarRecipientTest. Кнопки обычного чата и запросы из старых сообщений. |
| MorningDelivery | С 10:00 список содержит уже вручённые календари с подарком на сегодня. Публикация себе и поздний /start сразу резервируют одну доставку после коммита. Подтверждённая и неизвестная доставка имеют разные исходы. | TelegramTodayDeliveryTest, TelegramWidgetTest, повтор планировщика, 429, блокировка, потеря ответа. |
| User | Операторы видят данные через авторизованную панель и разрешения, тестовый вход доступен только локально. | StudioTest, производственные маршруты и доступ сотрудников. |

Связи и ограничения проверяются через Laravel/PostgreSQL migrations и feature tests. [Доменные модели](domain-models.md) связывают понятия с таблицами.
