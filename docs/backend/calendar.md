# Календарь подарков

## Данные и жизненный цикл

| Таблица и модель | Назначение и связи | Проверка |
| --- | --- | --- |
| `telegram_users` · `TelegramUser` | Числовой ID выдаёт Telegram. Последнее подтверждённое имя хранится в нижнем регистре и может отсутствовать. Один участник создаёт и получает несколько календарей. Смена имени сохраняет выданные подарки. | `TelegramUserFactory`, сценарии входа и смены имени в `CalendarFlowTest` |
| `calendars` · `Calendar` | Месяц хранится первым числом. При публикации по нику `recipient_id` заполняется при /start. При публикации по ID он задан заранее и резервирует месяц. В обоих случаях `claimed_at` фиксирует первое вручение. Подарок себе проходит оба перехода сразу. | `CalendarFactory`, сценарии публикации, конфликтов и параллельных запросов |
| `gift_days` · `GiftDay` | Записка принадлежит одной выбранной дате календаря. Дата хранится в московском календаре. Момент первого открытия фиксируется в `opened_at` и сохраняется при повторном чтении из любого сообщения. | `GiftDayFactory`, тесты полуночи, размера записки и конкурентного открытия |

Уникальность календаря в месяце обеспечивают два частичных индекса PostgreSQL. Один охватывает опубликованные календари в ожидании владельца ника, второй закреплённые за числовым ID. Черновики можно сохранять независимо. Если после смены ника на один ID претендуют два календаря за месяц, исходный остаётся у владельца, второй возвращается в черновики с `claim_conflict_at`. Тексты сохраняются.

Время вручения, публикации и открытия, а также текущая московская дата берутся из `GiftClock`. Локальная мастерская меняет эти часы для своего запроса. Срок действия подписи Telegram и ограничения частоты запросов отсчитываются по реальному времени.

## Границы кода

`App\Calendar\Contracts\CalendarRepository` описывает операции с календарём. `PostgresCalendarRepository` загружает модели и связывает их с неизменяемыми DTO. Редактору доступны только записки выбранного календаря автора. Mini App и ранее доставленный виджет получают результат из `OpenedGiftDTO` с текстом единственного открытого подарка и признаком первого открытия.

| Переход | Владелец |
| --- | --- |
| Подписанный вход в Mini App | `MiniAppLoginRequest` проверяет форму. `MiniAppIdentityVerifier` проверяет HMAC, время и ID. `RegisterTelegramUserAction` фиксирует подтверждённую личность. |
| Чтение редактора | `EditorPageService` возвращает `EditorPageDTO`. `CalendarPolicy` проверяет права автора перед чтением записок. |
| Чтение получателем | Сервис формирует представление месяца и состояния дат без текста. Экран конкретного дня проверяет вручение и дату. |
| Сохранение и публикация | `SaveCalendarAction` проверяет допустимые изменения. `PublishCalendarAction` проверяет полноту записок и через `CalendarPublicationService` проверяет, свободен ли месяц. |
| Вручение | `ClaimCalendarsAction` регистрирует имя и обрабатывает ожидающие публикации в одной транзакции. Бот получает только идентификаторы вручённых календарей. |
| Открытие | `OpenGiftAction` проверяет ID, адресата и московскую дату. Persistence-адаптер блокирует запись выбранного дня, отмечает первое открытие и возвращает результат. |

Миграция `2026_01_01_000001_create_calendars.php` задаёт поля, внешние ключи и ограничения. Команда `make test-suite suite=Calendar` проверяет HTTP, правила доступа, работу фабрик и конкуренцию двух независимых соединений PostgreSQL.
