# Проверить вручение и доставку

## Брифинг

Уполномоченный сотрудник проверяет факты публикации, вручения, отправки и открытия.

## Для пользователя

Войдите в панель Filament под учётной записью сотрудника. Откройте обзор и найдите участника или календарь.

## Основной сценарий

1. Найдите календарь и сверьте месяц и автора.
2. Проверьте подтверждённого получателя и время вручения.
3. Сопоставьте статус утренней карточки с числом открытых подарков.

Администратор создаёт роль или меняет её в разделе «Роли» панели. На вкладке страниц право `View:Overview` открывает обзор календарей, а `View:Handbook` — справочник, Scalar по адресу `/scalar` и JSON по адресу `/api/docs/openapi.json`. Дайте сотруднику только нужные права. Снятие галочки вступает в силу при следующем запросе.

Для первого администратора выполните `docker compose exec app php artisan advent:staff admin@example.org --super-admin`. Команда запросит пароль. Чтобы создать сотрудника поддержки, используйте эту же команду с его почтой без флага. Роль `support` по умолчанию открывает обе страницы.

Чтобы назначить существующую роль конкретному сотруднику, выполните `docker compose exec app php artisan advent:staff-role operator@example.org morning_shift`. В примере роль `morning_shift` уже создана в Shield. Команда заменяет все прежние роли этого сотрудника одной выбранной, пароль сохраняется.

## Альтернативные сценарии

Для вопроса об отсутствующем сообщении проверьте, опубликован и вручён ли календарь, наступило ли 10:00 МСК и есть ли подарок на текущую московскую дату. Поздняя публикация себе или /start запускают сегодняшнюю карточку сразу; затем проверьте очередь и статус доставки.

## Бизнес-правила

Учётные записи сотрудников отделены от идентификаторов участников Telegram. Управление ролями в панели доступно только роли `super_admin`. Учётная запись `local_preview` открывает обзор и справочник только в локальном окружении.

## Чеклист тестирования

Проверить доступ гостя, обычного пользователя бота и авторизованного сотрудника. Сравнить отправленную карточку до и после открытия.

## Зона риска

Успех вызова Telegram подтверждает отправку. О чтении говорит только сохранённое открытие.

## Связанные API

Панель и справка доступны через Filament. Продуктовые контракты, к которым относится обращение: publishCalendar, receiveTelegramUpdate. [Контракт](../backend/API_CONTRACT.md).

## Логи и следы

Сверьте идентификатор календаря, адресата, число открытий, дату и результат доставки; содержимое записки для такой диагностики не требуется.

## Ошибки

При отсутствии права сотрудник получает отказ в доступе. Неизвестный результат доставки сохраняют как самостоятельный исход.

## Готово, когда

Сотрудник может объяснить состояние календаря по наблюдаемым фактам.
