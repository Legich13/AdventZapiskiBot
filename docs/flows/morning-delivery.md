# Получить утреннее уведомление

## Брифинг

В 10:00 МСК начинается рассылка отдельного сообщения на сегодняшнюю дату.

## Для пользователя

Кнопка «К подарку» ведёт прямо к коробке нужной даты. Если подарок уже прочитан, сообщение предложит «Посмотреть ещё раз». В дни без подарка сообщения нет.

## Основной сценарий

1. Планировщик выбирает получателей сегодняшнего подарка.
2. PostgreSQL резервирует пару получатель–дата.
3. Воркер отправляет текст и кнопку Mini App.
4. По кнопке открывается экран дня. Записку раскрывает получатель в Mini App.

## Альтернативные сценарии

При публикации календаря себе с 10:00 МСК сегодняшнее уведомление поступает в очередь после коммита. Если календарь вручает бот через /start, сначала приходит открытка. Как только Telegram подтверждает её доставку, приложение запускает утреннее уведомление. Ответ 429 переносит повтор открытки на время `retry_after`. При неизвестном результате уведомление за день вручения ждёт подтверждения. Следующие даты обслуживаются по расписанию.

## Бизнес-правила

С 10:00 МСК учитываются все уже вручённые календари с подарком на текущую московскую дату. Черновик, невручённый календарь и будущее время вручения исключены. На получателя и дату создаётся одна доставка; повтор публикации, /start и планировщика не добавляет вторую карточку. Факт открытия утром не исключает участника. Известная ошибка и неизвестный результат сохраняются раздельно. Прошлые дни не досылаются.

## Чеклист тестирования

Проверьте 09:59, 10:00 и позднее вручение. При первом /start получатель видит открытку раньше утреннего текста. В день без подарка чат остаётся без уведомления. Перечитывание доступного подарка сохраняет прогресс.

## Зона риска

Повтор запроса с неизвестным исходом может дублировать уведомление. После окончания дня устаревшее задание прекращается.

## Связанные API

Планировщик действует внутри приложения. По кнопке запускается Mini App. За выдачу текста отвечает openReceivedGift. [Открытие записки](open-gift.md).

## Логи и следы

morning_deliveries содержит дату и статус. widget_messages хранит связь с подтверждённым сообщением. Факт прочтения смотрите отдельно в gift_days.

## Ошибки

Блокировка бота завершает отправку. При неоднозначном сетевом результате сервис не отправляет второе сообщение автоматически.

## Готово, когда

В локальном чате видно одно текстовое уведомление за день с кнопкой, соответствующей состоянию открытия.
