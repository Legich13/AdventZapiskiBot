# Правила Laravel

Системные правила и стабильные ARCH-ID находятся в [корневой архитектуре](../ARCHITECTURE.md). Структуру модулей и исполняемые примеры описывает [профиль backend](../docs/backend/README.md).

## Структура изменения

Маршрут сопоставляет HTTP с методом. FormRequest нормализует и валидирует запрос. Policy/Gate проверяет права. Контроллер вызывает Action для записи или Service для чтения. Предметный repository владеет запросами к PostgreSQL. Infrastructure изолирует Nutgram, Eloquent и конкретные хранилища. Для существующего межслойного значения фиксированной структуры используйте final readonly класс в каталоге DTO модуля с суффиксом DTO. Resource явно перечисляет поля для JSON. Изменение бизнес-состояния и транзакция принадлежат одной операции.

В файлах приложения объявляйте strict_types. PHPDoc модели содержит её назначение, таблицу, бизнес-процесс, источник проверки, жизненный цикл, ключи, типизированные свойства и связи. Фабрики создают валидные записи для тестов; демонстрационные данные отделены от обычного наполнения.

## Проверки

Сначала сохраните фактическое падение теста, затем пройдите его той же Make-командой. Pest-сценарии называйте по-русски через test(). Архитектурные тесты охватывают доступ к БД, форму DTO, документацию моделей и источники документации. Дополняйте их проверкой операций на PostgreSQL и публичных входов. Локальные команды, финальные проверки и эксплуатация описаны в [COMMANDS](../docs/COMMANDS.md). Новое поведение сопровождается изменением профильных страниц и процесса.

Для Laravel-задач подключите проектный Boost MCP через `make boost-mcp`. Сверьте окружение через `application-info` и получите релевантные рекомендации через `search-docs`. Клиентская настройка хранится в корневом .mcp.json. Для внешней документации используйте порядок Context7 из корневого AGENTS.md.
